# OpenClaw plugin

puppenclaw loads as a native OpenClaw plugin (id `puppenclaw`, peer dependency `openclaw >=2026.3.0 <2027`). The plugin
adds agent tools, the `/puppenclaw` command and gateway methods for ACP sessions, projects and campaigns, and ships the
agent skills in `skills/`.

## Install

From a checkout:

```bash
npm ci
npm run build
openclaw plugins install /path/to/puppenclaw
```

Or as a packed tarball: run `npm pack` after the build and install the `.tgz` it produces. Restart the OpenClaw gateway
afterwards. `dist/` is generated by the build and not committed.

In local mode the plugin keeps its state in the OpenClaw plugin state directory of the gateway (falling back to
`OPENCLAW_STATE_DIR`, then `.puppenclaw` under the working directory), never in the plugin checkout.

## Configure

Configure the plugin under `plugins.entries.puppenclaw.config`; the keys are listed in
[configuration.md](configuration.md).

```json
{
  "plugins": {
    "entries": {
      "puppenclaw": {
        "enabled": true,
        "config": {
          "backend": "local",
          "acpxCommand": "/usr/local/bin/acpx",
          "defaultAgent": "codex",
          "permissionMode": "approve-reads",
          "orchestration": {
            "defaultProjectRoot": "/srv/agent-workspaces",
            "localWorker": { "projectRoots": ["/srv/agent-workspaces"] }
          }
        }
      }
    }
  }
}
```

For daemon mode set `"backend": "daemon"`, `"daemonUrl": "http://127.0.0.1:18795"` and the daemon's
`daemonAuthToken`, and start the daemon separately (see the [README](../README.md#run-the-daemon)). The plugin then
forwards sessions and campaigns to the daemon.

ACP adapters run inside the gateway's environment and see its `HOME`, `PATH` and credentials. Run the gateway under a
dedicated `HOME` that holds the agents' logins, or wrap an adapter command, for example
`"agentCommands": {"codex": "env HOME=/srv/agent-home npx @zed-industries/codex-acp"}`, when it should use another account.

## Surfaces

**Campaign tools:** `puppenclaw_project_create`, `puppenclaw_worker_register`, `puppenclaw_context_sync`,
`puppenclaw_campaign_start`, `puppenclaw_campaign_status`, `puppenclaw_artifacts`, `puppenclaw_artifact_read`,
`puppenclaw_campaign_events`, `puppenclaw_campaign_approve`, `puppenclaw_campaign_cancel`,
`puppenclaw_reassessment_start`, `puppenclaw_reassessment_status`, `puppenclaw_reassessment_report`,
`puppenclaw_site_status`, `puppenclaw_logs`.

**Session tools:** `puppenclaw_start`, `puppenclaw_send`, `puppenclaw_status`, `puppenclaw_stop`, `puppenclaw_resume`,
`puppenclaw_suspend`, `puppenclaw_focus`, `puppenclaw_unfocus`, `puppenclaw_fork`, `puppenclaw_cost`.

**Command:** `/puppenclaw <verb> [json]` with the verbs `project`, `worker`, `sync`, `campaign`, `campaign-status`,
`artifacts`, `artifact-read`, `campaign-events`, `approve`, `cancel`, `reassess`, `reassess-status`,
`reassess-report`, `site-status`, `logs`, `start`, `send`, `status`, `stop`, `resume`, `suspend`, `focus`, `unfocus`,
`fork`, `cost`, and `bind`, `unbind`, `expose`, `hide` for remote control. `/puppenclaw` alone prints examples.

**Gateway methods:** `puppenclaw.projectCreate`, `puppenclaw.workerRegister`, `puppenclaw.contextSync`,
`puppenclaw.campaignRun`, `puppenclaw.campaignStatus`, `puppenclaw.artifacts`, `puppenclaw.artifactRead`,
`puppenclaw.campaignEvents`, `puppenclaw.campaignApprove`, `puppenclaw.campaignCancel`,
`puppenclaw.reassessmentStart`, `puppenclaw.reassessmentStatus`, `puppenclaw.reassessmentReport`,
`puppenclaw.usageCost`.

Tools cannot set the daemon-only fields `lifecycleEpoch` and `statisticsContext`.

## Local orchestration, step by step

1. Install and configure the plugin with at least `backend`, `defaultAgent` and `orchestration.defaultProjectRoot`,
   and restart the gateway.
2. Create a project. A relative `rootDir` resolves under `orchestration.defaultProjectRoot`:

   ```text
   /puppenclaw project {"name":"demo-project","rootDir":"demo-project","description":"Main repo"}
   ```

3. Register or confirm the worker:

   ```text
   /puppenclaw worker {"id":"local","label":"Local Worker","labels":["local"],"projectRoots":["/srv/agent-workspaces"]}
   ```

4. Capture context:

   ```text
   /puppenclaw sync {"projectId":"demo-project","includeFiles":["AGENTS.md","README.md"],"memoryText":"Use npm, run tests."}
   ```

5. Run a campaign:

   ```text
   /puppenclaw campaign {"projectId":"demo-project","workerId":"local","name":"baseline","template":"baseline_from_scratch","task":"Implement the first working baseline.","evaluationCommand":"npm test"}
   ```

6. Inspect it with `campaign-status`, `artifacts` and `campaign-events`, and resume a campaign that waits for approval
   with `/puppenclaw approve {"campaignId":"camp-..."}`.

## Campaign templates

| Template | What it runs |
| --- | --- |
| `literature_review` | A `research` step; with `orchestration.gptResearcherCommand` set, that command runs instead and its stdout is stored as a `research-dossier` artifact. |
| `baseline_from_scratch` | Plan, implement, and evaluate with `evaluationCommand` when given. |
| `ablation_campaign` | The given `experimentCommands` (`experimentParallelism` 1–16), for experiments you already know. |
| `self_improvement_loop` | Planning, implementation, optional evaluation and review, repeated `iterations` times (1–10). |
| `puppenfusion` | Codex and Claude work from the same sealed brief, review each other, and their candidates are merged. |
| `custom` | Your own `steps`, each `{title, kind, executor: "acp" or "command", instruction or command, ...}`. |

A `research` command receives the step prompt on stdin, must print the dossier on stdout and sees
`PUPPENCLAW_PROJECT_ID`, `PUPPENCLAW_PROJECT_NAME`, `PUPPENCLAW_PROJECT_ROOT`, `PUPPENCLAW_CAMPAIGN_ID`,
`PUPPENCLAW_CAMPAIGN_NAME`, `PUPPENCLAW_STEP_ID`, `PUPPENCLAW_STEP_TITLE` and `PUPPENCLAW_TASK`. `command` steps and the
evaluation and experiment commands need `orchestration.allowLocalCommandExecution` (or a worker registered with
`executors: ["acp", "command"]`).

### puppenfusion

A `puppenfusion` campaign:

- requires a clean git worktree at campaign start and creates separate local worktrees for the Codex candidate, the
  Claude candidate and the merged candidate;
- gives both planning and implementation runs the same sealed bundle: task, scope and non-scope, constraints,
  validation plan, synced project context and the exact base commit;
- runs a planning round first (a structured plan review from each agent, synthesized into one fusion plan) and pauses
  for approval before implementation;
- requires a structured implementation memo from both runs and records a candidate handoff artifact per agent with
  commit and validation metadata;
- runs fresh cross-reviews (Codex reviews the Claude candidate and the other way round) and synthesizes a fusion dossier,
  optionally sent to `orchestration.fusionArbiterCommand` when the campaign sets `useExternalArbiter`;
- integrates the candidates with local git first and falls back to one resolver pass by `fusionPreferredAgent` only when
  automatic integration reports a conflict or an unresolved path.

`fusionPreferredAgent` defaults to the project's `fusionPreferredAgent`, then its `defaultAgent`, then the plugin's
default agent.

### Reassessment

`/puppenclaw reassess {"projectId":"demo-project","workerId":"local","targetModel":"gpt-new","providers":["puppenclaw","codex","claude"],"validationCommand":"npm test"}`
imports matching earlier puppenclaw, Codex and Claude Code sessions of the project, creates a new branch and worktree,
asks the target model to patch only concrete mistakes of the earlier model, runs validation and stores a report. The
base branch is never merged automatically.

## Raw ACP sessions

Raw sessions give an operator direct ACP control; use campaigns when the work is project-shaped:

```text
/puppenclaw start {"agent":"codex","name":"api-refactor","directory":".","task":"Implement the server side."}
/puppenclaw send {"name":"api-refactor","message":"Continue and run tests.","stream":true}
/puppenclaw status {}
/puppenclaw stop {"name":"api-refactor"}
```

## ACP verification

Before blaming puppenclaw, prove the ACP stack from the same `HOME` and working directory the gateway or daemon uses:

```bash
/usr/local/bin/acpx --help
HOME=/path/to/agent-home /usr/local/bin/acpx --format json --json-strict --cwd /path/to/project \
  codex sessions new --name smoke-test
printf '%s' 'Reply with exactly OK and stop.' | HOME=/path/to/agent-home /usr/local/bin/acpx \
  --format json --json-strict --cwd /path/to/project --approve-reads --non-interactive-permissions deny \
  codex prompt --session smoke-test --file -
```

Repeat with `claude` for Claude Code. Start sessions through puppenclaw only after these succeed.

## oc2oc remote control

In an `oc2oc` conversation with another OpenClaw peer, `/puppenclaw` commands from the remote side run only when:

1. `remoteControl.purePipe.enabled` is true;
2. the conversation is bound: `/puppenclaw bind` (detach with `/puppenclaw unbind`);
3. the binding is exposed: `/puppenclaw expose {"agents":["codex"],"allowPurePipe":true,"mode":"execute","allowedVerbs":["campaign","campaign-status","logs"],"allowedProjectRoots":["/srv/agent-workspaces"]}`
   (defaults: every agent and verb, `execute` mode, any root; `/puppenclaw hide` removes the exposure).

In `read-only` mode only the inspection verbs run: `campaign-status`, `artifacts`, `artifact-read`, `campaign-events`,
`reassess-status`, `reassess-report`, `site-status`, `logs`, `status` and `cost`. The work itself runs locally on the
target node; there is no typed puppenclaw transport inside `oc2oc` beyond these commands.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| `Project root does not exist` | `orchestration.defaultProjectRoot`, and whether `rootDir` was meant to be absolute or relative. |
| `Worker ... is not allowed to operate on ...` | The worker's `projectRoots`; register it again with the right roots. |
| `Worker ... does not support command execution` | Enable `orchestration.allowLocalCommandExecution`, register the worker with `executors: ["acp", "command"]`, or use a campaign without command steps. |
| `Puppenclaw daemon is unreachable` | Start the daemon, check `daemonUrl`, run `node dist/daemon/cli.js status --host … --port …`. |
| `spawn acpx ENOENT` | acpx is not installed or `acpxCommand` is wrong. |
| `Authentication required` | The adapter sees no valid login in the gateway's `HOME`; log in there or wrap the adapter with `env HOME=…`. |
| `acpx exited with code 4` | Run the same acpx command by hand with the gateway's `HOME` and working directory; it is an adapter error until that works. |
| `No acpx session found` | The ACP session was never created, or is not visible from the current `HOME`. |
